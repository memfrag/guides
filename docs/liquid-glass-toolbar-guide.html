The headline behavior

Why Do Toolbar Items Share One Liquid Glass Background?

In iOS 26, SwiftUI toolbar items are not guaranteed to receive one independent capsule per ToolbarItem. In navigation bars and some other toolbar contexts, the system gives items a glass background that can be shared with other items in the same logical grouping.

That grouping is influenced by placement, proximity, explicit ToolbarItemGroup declarations, spacers, and APIs that hide or show shared backgrounds. The system is trying to communicate relationships, not merely draw a border around every declaration in code.

Good rule: group controls by meaning. If two actions are part of the same job, sharing one glass surface is helpful. If they start different workflows, give them visual separation.
The separator

Use ToolbarSpacer for Visual Breaks

ToolbarSpacer is the iOS 26 SwiftUI tool for creating visual breaks in a toolbar. Fixed spacers create standard separation; flexible spacers expand and push items apart.

Fixed Spacer

Use when controls should remain near each other but live on separate glass surfaces.

ToolbarSpacer(.fixed, placement: .topBarTrailing)

Flexible Spacer

Use when you want available toolbar space to separate groups more dramatically.

ToolbarSpacer(.flexible)

When the surrounding items use .topBarTrailing, match the spacer placement explicitly. That makes the grouping intent clearer to SwiftUI and clearer to future readers of the code.

Code Examples

Original Shape, With Explicit Spacer Placement

.toolbar {
    ToolbarItem(placement: .topBarTrailing) {
        filterButton
    }

    ToolbarSpacer(.fixed, placement: .topBarTrailing)

    ToolbarItemGroup(placement: .topBarTrailing) {
        Button("Add Product...", systemImage: "plus") {
            router.presentSheet(.addProduct)
        }

        Button {
            router.presentSheet(.scanner(.registry))
        } label: {
            Label("Scan Products", systemImage: "barcode.viewfinder")
        }
    }

    ToolbarSpacer(.fixed, placement: .topBarTrailing)

    ToolbarItem(placement: .topBarTrailing) {
        transferMenu
    }
}

Every Item on Its Own Surface

.toolbar {
    ToolbarItem(placement: .topBarTrailing) { filterButton }
    ToolbarSpacer(.fixed, placement: .topBarTrailing)
    ToolbarItem(placement: .topBarTrailing) { addButton }
    ToolbarSpacer(.fixed, placement: .topBarTrailing)
    ToolbarItem(placement: .topBarTrailing) { scanButton }
    ToolbarSpacer(.fixed, placement: .topBarTrailing)
    ToolbarItem(placement: .topBarTrailing) { transferMenu }
}

Opting Out of a Shared Background

.toolbar {
    ToolbarItem(placement: .topBarTrailing) {
        Button("Help", systemImage: "questionmark.circle") {
            showHelp()
        }
    }
    .sharedBackgroundVisibility(.hidden)
}

Use sharedBackgroundVisibility(.hidden) carefully. It can be useful for a special control, but ToolbarSpacer(.fixed) is usually the better expression when you simply need separate groups.

Grocery app recommendation

Recommended Product Toolbar

For a grocery product registry, these actions form three concepts: filtering, creating products, and transferring or managing products. Add and Scan belong together because both create product entries.

Recommended visual structure: [ Filter ] [ Add | Scan ] [ Transfer ] 
@ToolbarContentBuilder
private var productToolbar: some ToolbarContent {
    ToolbarItem(placement: .topBarTrailing) {
        filterButton
    }

    ToolbarSpacer(.fixed, placement: .topBarTrailing)

    ToolbarItemGroup(placement: .topBarTrailing) {
        Button("Add Product...", systemImage: "plus") {
            router.presentSheet(.addProduct)
        }

        Button {
            router.presentSheet(.scanner(.registry))
        } label: {
            Label("Scan Products", systemImage: "barcode.viewfinder")
        }
    }

    ToolbarSpacer(.fixed, placement: .topBarTrailing)

    ToolbarItem(placement: .topBarTrailing) {
        transferMenu
    }
}

Compact Alternative

If space gets tight on iPhone, combine creation methods into a menu and keep scanning one tap deeper.

ToolbarItem(placement: .topBarTrailing) {
    Menu("Add Product", systemImage: "plus") {
        Button("Add Manually...", systemImage: "square.and.pencil") {
            router.presentSheet(.addProduct)
        }

        Button("Scan Barcode", systemImage: "barcode.viewfinder") {
            router.presentSheet(.scanner(.registry))
        }
    }
}
Design judgment

Liquid Glass Design Guidance

Do

  • Use standard Button, Menu, ToolbarItem, and ToolbarItemGroup.
  • Prefer semantic placements such as .confirmationAction and .cancellationAction when they fit.
  • Keep meaningful labels even when the toolbar currently shows only icons.
  • Use badges for real counts or states, such as selected filters or pending uploads.
  • Test over real scrolled content, photos, dark mode, and accessibility settings.

Avoid

  • Forcing every icon into a separate capsule when the actions are related.
  • Putting unrelated actions into one large shared surface.
  • Applying glassEffect() to normal toolbar controls that already receive system styling.
  • Keeping old opaque toolbar backgrounds unless they serve a deliberate design need.
  • Assuming all toolbar items will remain visible; overflow is adaptive.
UIKit equivalent

UIKit Notes

UIKit bar button items also participate in shared backgrounds. UIBarButtonItem includes sharesBackground, which indicates whether an item can share a background with neighboring items in a navigation bar or toolbar.

let filterItem = UIBarButtonItem(
    image: UIImage(systemName: "line.3.horizontal.decrease"),
    primaryAction: UIAction { _ in showFilters() }
)

filterItem.sharesBackground = false

This does not override grouping when the item belongs to a multi-item UIBarButtonItemGroup. For SwiftUI-first screens, prefer the SwiftUI grouping APIs unless you are already managing UIKit navigation items directly.

Accessibility and Testing Checklist

  • Light mode
  • Dark mode
  • Increased Contrast
  • Reduce Transparency
  • Reduce Motion
  • Large accessibility text sizes
  • Landscape orientation
  • Narrow iPad windows
  • Long localized button titles
